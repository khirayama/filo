フィード取得 & パース Queue
jobs/fetchFeed.ts · lib/feed.ts

Queue Consumer がジョブを受け取り、RSSフィードをHTTPで取得してパースする。

  1. 条件チェック
    paused フィードは refresh をスキップ（retry_initial は許可。成功すると active に復帰）。
  2. HTTP取得（条件付きリクエスト）
    ETag / If-Modified-Since ヘッダーで帯域を節約。304 Not Modified なら即完了し、next_fetch_after = +120分。
    headers: { "If-None-Match": etag, "If-Modified-Since": lastModified }
  3. XML パース
    RSS 2.0 / Atom / RDF を統一的にパースし、ParsedFeed 構造に変換。
  4. フィードメタデータ更新
    title, site_url, description, language, favicon_url を feeds テーブルに反映。favicon 失敗は取得を止めない。
  5. 記事の重複排除 & 保存
    guid → canonical URL → title+date+author ハッシュ の優先順位で dedupe_key を生成。既存記事は更新、新規記事は INSERT（最大200件/フィード）。
    dedupe_key: guid:xxx | url:xxx | hash:sha256(title|date|author)
  6. fetch_state 更新 & ログ記録
    成功時: next_fetch_after = +30分、consecutive_failures = 0。feed_fetch_logs に結果を記録。翻訳ジョブの自動投入は行わない（rate limit 保護のため手動のみ）。

一覧表示用タイトル翻訳 Manual AI
jobs/translateDrain.ts · lib/translate.ts

記事一覧で表示するタイトルを、ユーザーの手動操作で翻訳する。翻訳結果は記事補足データとして共有保存し、ユーザーごとに複製しない。プレビュー翻訳・要約は行わない。

  1. トリガー: ステータス画面の手動ボタン
    POST /status/translate（全購読） / POST /status/translate/:feedId（個別）。不足している (article, language) ペアを article_listing_translations に status=pending で一括投入し、error 行も pending に戻して再試行する。
  2. グローバル drain がバッチ翻訳
    専用キュー filo-translate（max_concurrency=1）の drain が pending 行を feed 横断・同一原文言語で最大40件ずつまとめ、1リクエストで対象言語すべてを LM Studio に翻訳させる。id キー付き JSON で突き合わせ、429 は delaySeconds 付き再投入で待つ。
  3. 翻訳結果を共有保存（表示可能性を検証）
    最新の判定方針: 空出力・必要な翻訳先への完全 echo・明らかな別言語は修復後も失敗扱いにする。文字種混在や固有名詞由来の不確かさは警告として、非空かつ原文完全 echo でない結果を ready にする。警告は翻訳失敗数や error_message には反映しない。
    検証（echo・言語違いの排除）を通った訳のみ ready に更新。失敗は attempt_count+1 で pending に留め、3回で error 確定。進捗・完了・失敗の表示はすべて翻訳行の集計（coverage）から導出する。

本文抽出（リーディングパート用） Manual
jobs/extractContent.ts · routes/content.ts

本文はリーディングパート（音読キュー）のためだけに扱う。RSSリーダーパートの一覧・詳細では本文を扱わず、要約は生成しない。 本文翻訳もアプリでは提供せず、各プラットフォーム / ブラウザの翻訳機能に委ねる。翻訳して聴きたい場合は、翻訳機能を適用した後の可視コンテンツを音読キューに取り込む。

  1. トリガー: ユーザーリクエスト
    POST /articles/:id/content。音読キュー追加時にも必要に応じて要求される。
  2. RSS本文を優先、なければ元ページから抽出
    RSS content:encoded / summary から抽出し、足りなければ canonical_url の HTML を取得して本文抽出（nav / sidebar / footer 等のノイズを除去）。
  3. article_contents に共有保存
    text / html / source_language を保存。失敗時は status=error を記録し再試行できる。
⚙
使用AIモデル
lib/translate.ts

AI 処理はタイトル翻訳のみで、LM Studio の OpenAI 互換 API（デフォルト http://localhost:1234/v1）を利用する。モデルは TRANSLATION_MODEL（既定 google/gemma-4-12b-qat）で指定し、 サーバー環境変数 TRANSLATION_MODEL で切り替える（ユーザーによるモデル選択はない）。 id キー付き JSON 形式で応答させ、プロンプトに応答が混ざるモデル向けの救済パースを持つ。 ペーシングは実測トークン（usage.total_tokens）から計算し、TRANSLATION_TOKENS_PER_MINUTE（既定10,000）以下の持続レートに保つ。

エラーハンドリング & リカバリー
index.ts · jobs/fetchFeed.ts

失敗はステータスとして可視化し、ユーザーの手動操作で復旧する。cron が自動でコンテンツ処理を再開することはない。

フィード取得失敗
指数バックオフ: 15分 → 60分 → 360分。
3回連続失敗で feed.status = paused。
retry-initial-fetch の成功で active に復帰。
翻訳 / 抽出失敗
status=error を記録し、ステータス画面から手動で再実行（force）。
自動回収は行わない。
Queue / cron
Queue のジョブ失敗は 60秒後にリトライ。
cron（毎時）は失敗した account deletion job の再投入のみ（最大5回）。

配信（API レスポンス）
routes/articles.ts · routes/content.ts · routes/playbackQueue.ts

ユーザーの言語設定に応じて翻訳済みデータを返す。

  1. 記事一覧
    ソース言語がユーザーの readableLanguages に含まれなければ翻訳タイトルを使用。含まれる場合は原文表示を優先できる。
  2. 本文コンテンツ
    GET /articles/:id/content が状態（pending / ready / error）付きで返し、クライアントは pending をポーリングして完了を検知。
  3. 読み上げキュー
    playback-queue API がキュー・再生中記事・再生位置を保持し、iOS / Android / Web + Extension で共有。読み上げ開始時に既読化する。翻訳して聴く場合は、プラットフォーム / ブラウザの翻訳適用後の可視コンテンツをキュー追加時に取り込む。
