# filo Screens

## 画面

- サインアップ・サインイン
- 購読一覧／購読管理
- フィード追加
- タグ管理
- 購読記事一覧
- 処理ステータス
- 設定
- アカウント削除

## 記事一覧

- `/articles` を起動後の主要画面とする。
- 全購読、購読単体、タグ、リーディングリスト、ブックマークの一覧を表示する。
- 記事には feed 名、タイトル、RSS プレビュー、時刻、既読状態、リーディングリスト状態、ブックマーク状態を表示する。
- 記事一覧は既読／未読で絞り込みでき、各記事を明示的に既読／未読へ変更できる。
- 既読／未読、リーディングリスト、ブックマークの変更は操作と同時に一覧へ反映し、API の失敗時は元の状態へ戻してエラーを表示する。「すべて既読にする」も同時に反映し、画面をブロックしない。
- 記事の行全体が記事を開くタップ領域で、押下中は行をハイライトする。フィード名・翻訳トグル・行内アイコンはそれぞれの操作を優先する。
- iOS / Android は行内アイコンの操作時に軽い触覚フィードバックを返す。行のスワイプ操作は持たない。
- アイコンは意味ごとに分ける: 行の既読はチェック丸、「すべて既読にする」は二重チェック、一覧の「表示設定」と「読み上げ設定」はスライダー、歯車はアプリの「設定」だけに使う。
- 記事タップでは元記事 URL を開く。
- リーディングリストは記事一覧として表示する。連続再生やキュー操作は提供しない。
- リーディングリストのアイテムをクリックすると元記事URLを開き、各アイテムからリーディングリスト登録を解除できる。
- リーディングリストには、確認後に既読記事をまとめて削除するボタンを置く。
- リーディング画面（iOS / Android のアプリ内ブラウザ、Browser Extension のポップアップ）は同じ操作をそろえる: 主ボタン「このページを読み上げ」（読み上げ中・準備中は「読み上げを停止」）、「リーディングリスト」、「リストに追加」、「選択範囲を読み上げ」（選択中のみ有効）、声・言語・速度設定、エラー表示。読み上げ対象の切り替え設定は持たない。
- iOS / Android のリーディング画面は同じ構成にする: ヘッダに再生／停止ボタン、ページの下に 1 行のツールバー（リスト、追加、選択範囲を読み上げ、読み上げ設定）。声・言語・速度は「読み上げ設定」のシートに置く。
- Android の読み上げ通知（メディア通知）は読み上げを開始したときに表示する。一時停止中は残し、読み上げ完了・別の記事への移動・リーディング終了で消す。リーディング画面を開いただけでは表示しない。
- 任意 URL の閲覧中もリーディングリストを開いて記事を選べる。現在ページの追加成功時は保存された記事 ID を反映し、ブラウザのページを維持したままリスト表示へ追加する。
- Browser Extension のポップアップはログイン状態によらず現在のページを読み上げられる。追加操作はログインを要求し、ログイン中はリーディングリストを表示して現在のリーディングブラウザの記事を強調する。リストの記事を選ぶとリーディングブラウザのタブで開く。別タブで読み上げ中の場合はミニプレーヤー（タイトルと停止）を表示する。
- Web 本体の Browser Extension が未インストールまたは未検出の場合、リーディングリストの閲覧開始・読み上げ開始ボタンは無効にする。
- 記事一覧・購読詳細の表示中は約30秒ごとに新着を確認する。非表示・バックグラウンドでは停止し、復帰時に確認する。現在の購読・タグ・既読・リスト条件に合う新規記事があれば「新着記事があります」を一覧上部に重ねて表示する。
- 新着の検出だけでは一覧やスクロール位置を変更しない。通知を押すと現在の絞り込み・並び順で再読込して先頭へ移動する。この操作では feed fetch を開始しない。確認の通信失敗は閲覧を妨げず次回再試行する。
- 記事一覧の更新は feed fetch を enqueue し、status API の完了後に一覧を再読込する。
- 更新の入口は、記事一覧（全ての記事・タグ）と購読詳細のヘッダの更新ボタン、`R` キー、一覧の先頭でのプルして更新（Web はタッチ操作時）。完了待ちの間は「フィードを更新しています…」を示し（Web は更新ボタンのアイコンを回す）、完了後の通知は「N件のフィードを更新しました。」とする。
- 同じ一覧の再読込では表示中の記事を残したまま差し替える。一覧を切り替えたときだけ読み込み中表示にする。
- 購読詳細の更新は対象 feed だけを enqueue し、status API の完了後にその購読の記事一覧を再読込する。
- 翻訳トグルを 1 つ持ち、表示中の記事タイトルを端末内翻訳する。
- 翻訳済みタイトルは行ごとに原文へ戻せる。
- スクロールで追加された記事も、翻訳トグルが有効なら翻訳対象にする。
- 購読がない場合はフィード追加導線を表示し、取得中は取得状態を表示する。
- ブラウザ拡張のポップアップと iOS / Android の共有シートから任意 URL をリーディングリストへ追加できる。
- iOS の共有拡張は URL を本体へ引き継ぎ、次回起動時に追加画面を表示する。続けて共有した URL は上書きせず順番に表示し、追加またはキャンセル後に次の URL へ進む。

## リーディング状態

- 記事を開くだけ、一時停止しただけでは既読にしない。
- 読み上げ完了時は対象記事を既読にする。記事間の自動遷移は行わない。
- フィード由来の記事と、ブラウザ／共有から保存した任意 URL を対象にする。
- 読み上げる文章は表示中の文章 → Readability の本文抽出 → サーバーの保存済み本文抽出の順に取得する（[APP.md](./APP.md)）。抽出漏れよりも本文ノイズを許容する。

## ナビゲーションの操作

- ドロワーは 3 プラットフォームとも全幅で開く。iOS / Android は指に追従する: Android は標準のモーダルドロワーで、メニューボタンのある画面では横ドラッグでも開く。iOS は記事一覧の左端からのドラッグで開き、パネルを左へドラッグして閉じる。
- 一覧の「表示設定」は 3 プラットフォームともボタン直下のポップオーバーで開く。
- iOS のアプリ内ブラウザは、ページ履歴の戻る／進むスワイプに対応する。
- 画面遷移は 3 プラットフォームとも横スライドにする: 進むときは右から、戻るときは左から。記事一覧の中の切り替え（タグ、リーディングリスト、ブックマーク）は遷移させない。Web は入ってくる画面だけを動かす。Android は予測型「戻る」に対応する。
